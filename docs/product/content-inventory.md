# Content Inventory and Verification Register

## Purpose

This is the single register for content that may appear in the portfolio. A record may move to **Approved for publication** only when Marcos confirms the exact wording, language(s), and any required permission.

## Status vocabulary

- **Known internally:** available as planning context; not publishable.
- **Needs owner input:** no content has been supplied.
- **Approved for publication:** owner has confirmed wording and use.

## Case studies

Each selected case must have its own record before any public copy is drafted.

| Field | Required for approval |
| --- | --- |
| Public title | A non-confidential title or anonymized description |
| Context | Product/domain and the problem being solved |
| Role | Marcos's actual role and level of ownership |
| Constraints | Technical, organizational, privacy, scale, or delivery constraints that may be shared |
| Decision | Key technical decision and alternatives/trade-offs |
| Evidence | Permitted architecture excerpt, code link, screenshot, demo, or owner-approved narrative |
| Outcome | Verifiable result, or an explicit qualitative outcome without fabricated metrics |
| Permission | Confirmation that employer/client confidentiality permits the content |
| Languages | Owner-approved English source and Spanish translation/review |

## Editorial guardrails

- Do not use company names, logos, source code, screenshots, customer data, or metrics without explicit publication permission.
- When a metric cannot be published, describe the engineering outcome plainly and avoid numerical substitution.
- Use first person only for responsibilities Marcos confirms personally.
- Keep English as the source copy only after it is owner-approved; Spanish must be reviewed rather than mechanically assumed final.
